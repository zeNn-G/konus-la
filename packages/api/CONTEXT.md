# API

ORPC router and procedures. The `appRouter` is the typed contract between server and web.

## Language

- **Procedure** — a typed RPC operation (input schema → handler → output).
- **Public Procedure** — no auth required.
- **Protected Procedure** — requires an authenticated session; the auth middleware exposes `session` + `user` to the handler.
- **Admin Procedure** — builds on Protected; additionally requires the global `admin` role (the Instance Owner, ADR 0002).
- **Guild Member / Guild Owner middleware** — the per-guild access tier (`requireGuildMember` / `requireGuildOwner`; see [ADR 0004](../../docs/adr/0004-per-guild-authorization-custom-rbac-tables.md)). They gate on a `guildId` from **validated input**, so they are chained **after** `.input()` rather than baked into a base procedure: `protectedProcedure.input(...).use(requireGuildOwner)`. Member = belongs to the guild (also drives no-peek); Owner = `guild.ownerId`.
- **Channel Member middleware** — `requireChannelMember`, for procedures keyed by `channelId`: loads the channel, requires the caller to belong to it — guild membership for guild channels, a **ChannelParticipant** row for DMs (`guildId` null) — and injects the loaded `channel` (now with `isGroup`/`ownerId`) into context so handlers don't re-query. Fan-out mirrors the same split via `channelRecipientUserIds` (`src/realtime/publishers.ts`): guild members or DM participants.
- **Ratelimit middleware** — `perUserRatelimit(rule, limiter)` in `src/ratelimit.ts` (`@orpc/experimental-ratelimit`, in-memory sliding windows, keyed `rule:userId`, throws TOO_MANY_REQUESTS). Rules: sendMessage 30/10s, markRead 60/min, typing 1/s, inviteCreate 5/hr, dmOpen 30/min, dmCreateGroup 10/hr, dmMutate (add/remove/leave/rename) 30/min, userSearch 20/10s, voiceJoin (join+leave shared) 10/min, voiceFlags (mute+deafen shared) 10/10s, voiceSignal (createTransport/connectTransport/produce/closeProducer shared) 15/10s, voiceConsume (consume+setConsumersPaused shared) 60/10s. `voice.getRouterRtpCapabilities` is unlimited (read).
- **Context** — per-request value passed to every procedure handler. Carries `{ headers }` plus, for calls arriving over `/ws`, the socket's `connectionId`; the Better Auth session is resolved **lazily** inside the auth middleware (so public procedures skip `getSession`), following the oRPC × Better Auth integration pattern.
- **Routers** — `signupCode` (create / list / revoke, admin-only), `profile` (update displayName), `user` (`search` / `get` — the instance-wide public directory powering the DM pickers; distinct from `profile`'s self-mutations), `guild` (`create` / `list` / `get` / `transferOwnership` / `delete`, nested `guild.invite` + `guild.member`), `channel` (create / update / delete / list / markRead), `chat` (sendMessage / editMessage / deleteMessage / history), `typing` (start), `dm` (openWithUser / createGroup / addParticipant / removeParticipant / leave / rename / list / get — see [ADR 0006](../../docs/adr/0006-participant-keyed-dm-channels.md)), `realtime` (events), `voice` (join / leave / setSelfMute / setSelfDeaf + the media ceremony: getRouterRtpCapabilities / createTransport / connectTransport / produce / closeProducer / consume / setConsumersPaused — see Room/Peer below), alongside `healthCheck`.
- **DM event conventions** — `guildId: null` on `message.*` / `typing` / `channel.created|updated` marks a DM-channel event (clients route to the DM list instead of a guild sidebar). `dm.participant.added/removed` are the roster events; **receiving `dm.participant.removed` with your own userId is the ONE "this DM is gone for you" signal** — `channel.deleted` never fires for DMs (the last leaver's deletion publishes `removed` to the leaver alone). `dm.openWithUser` publishes nothing: the draft flow means the first `message.created` is what introduces the conversation to the recipient. In DMs, message deletion is author-only (the group owner moderates people, not messages).
- **Guild membership events** — `guild.member.added/removed` fan out to the guild's remaining members plus the affected user (join via `invite.consume`, kick, ban, `member.leave`). **Receiving `removed` with your own userId is the "this guild is gone for you" signal** — clients evict (mirror of the DM convention above); co-members just refresh the roster. `added` with your own userId clears a stale eviction tombstone (rejoin after a kick). Ownership transfer publishes **`guild.updated`** (all members re-read `guild.get` — owner flags and crown flip live); guild deletion snapshots the roster before the FK cascade and publishes **`guild.deleted`**, which evicts every recipient with no per-user check.
- **Publisher** — process-lifetime in-memory event bus (`MemoryPublisher<EventMap>`, `resumeRetentionSeconds: 120` for `lastEventId` resume). Singleton at `src/realtime/publisher.ts`. Mutations fan out via **`publishTo(userIds, event)`** (`src/realtime/publishers.ts`) to per-user topics; the `realtime.events` iterator subscribes to the caller's own topic. See [ADR 0005](../../docs/adr/0005-per-user-topic-realtime-hybrid-transport.md).
- **RealtimeEvent / EventMap** — the discriminated union of server→client events and its `user:{userId}` topic map (`src/realtime/events.ts`). Adding a realtime feature = add a union variant, compute recipients, `publishTo`.
- **Presence** — in-memory open-socket counts + 5 s debounced offline broadcast (`src/realtime/presence.ts`). Lives here (not `apps/server`) because the events iterator reads the snapshot synchronously at subscribe; the server's socket hooks call `presenceConnectionOpened/Closed`.
- **Room** (voice, Phase 5) — in-memory state for one occupied voice channel (`src/voice/rooms.ts`), created lazily on first join — including its mediasoup **router + AudioLevelObserver** (Opus DTX+FEC + VP8, `src/voice/sfu.ts`; the worker handle is injected by apps/server via `setSfuWorker`, and `mediasoup` is a type-only import here) — capped at 20 seats (a full room joins as CONFLICT; rebinds/steals are exempt — no new seat), GC'd immediately when the last seat empties (router close cascades; closing a dead router is a no-op). **Never persisted** — there is no voice table (the ROADMAP's "VoiceState" is retired); a server restart empties every room by definition, so occupancy is only ever a published view of this memory. That view = `voice.snapshot` yielded by `realtime.events` right after `presence.snapshot` (no fetch path; reconnects re-sync by resubscription) plus guild-wide `voice.peerJoined/peerLeft/peerMutedSelf/peerDeafenedSelf/activeSpeakers`. `voice.activeSpeakers` is **edge-triggered**: the observer's ~500 ms interval is the debounce and the server publishes the full speaking set only when it changes (`updateSpeakingUserIds`); producer churn (`voice.producerAdded/producerClosed`) is **room-only** — current seats, not the guild. Every successful `voice.join` bind additionally **replays the room's live producers to the joiner alone** (self-only `producerAdded` — the late joiner's / rebinder's consume trigger; existing seats hear nothing again).
- **Seat** (voice, Phase 5) — a user's guild-visible membership in a Room; one seat per user instance-wide (`voice.join` elsewhere implicitly unseats, carrying the self flags). A seat outlives its socket for a 30 s grace (media torn down, occupancy unchanged — the `websocket.close` hook calls `voiceConnectionClosed`), and every bind mints a **seat-session id** — a multi-tab steal names the replaced id in the self-only `voice.sessionReplaced` so only the losing tab tears down; grace rebinds and same-socket rejoins publish nothing.
- **Peer** (voice, Phase 5) — the connection-level media half of a seat: the owning socket plus its mediasoup transports/producers/consumers and the server-enforced ceremony state machine `joined → transportCreated → connected → producing` (`src/voice/media.ts`; out-of-order or wrong-socket calls are VOICE_INVALID_STATE). Media policy: 1 mic + ≤1 screenAudio + ≤1 cam + ≤1 screen per peer (**screenAudio** = the audio half of a screenshare, an audio-kind producer source alongside mic; only mic producers join the room's AudioLevelObserver, so share audio never registers as speaking), `setMaxIncomingBitrate` backstop on the send transport (env `MEDIASOUP_MAX_INCOMING_BITRATE`), consumers **created paused** with batched `setConsumersPaused` as the only activation verb (unknown ids are skipped — closed-consumer races are normal; only the caller's own consumers are ever touched, no broadcast). Deafen's server half lives in `setSelfDeaf`: pause/resume of the peer's audio consumers, and `setConsumersPaused` refuses to resume audio while deafened. The Peer dies with the socket (room hears `producerClosed`); the seat it served enters grace. SFU worker death graces every seat at once (silently, handles discarded, `router = null`); the respawn publishes self-only `voice.mediaReset` so seated clients re-run `voice.join`, which rebuilds routers lazily.
- **Voice availability** (`src/voice/availability.ts`) — the down-state flag behind the SFU crash-loop breaker (`apps/server/src/sfu/` flips it via `setVoiceDown`). `voiceProcedure` is the base builder for every `voice.*` procedure: it declares the defined `VOICE_UNAVAILABLE` (503) and `VOICE_INVALID_STATE` (409) errors, fails fast while voice is down, and **rejects non-WS calls** — context without a `connectionId` (i.e. fetch `/rpc`) gets FORBIDDEN, per ADR 0007. Defined errors ride on `instanceof ORPCError`, so `@orpc/*` versions must stay on one minor or `VOICE_*` surfaces as 500s.
